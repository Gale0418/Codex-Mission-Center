# Mission Center 0.5.2

0.5.2 extends the Rust-only Mission Center runtime with bounded contextual recall,
explicit preflight decisions, derived commitment closure, and explicit external-operation
reconciliation. `MissionCenter/tasks.md` remains the only task lifecycle truth.

## Highlights

- Bounded, source-backed context cards for named operation boundaries; no broad workspace
  scan, vector database, daemon, or implicit task mutation.
- Read-only preflight that distinguishes `covered`, `not-covered`, and `unknown`, and
  fails closed on stale, incompatible, corrupt, or required missing context.
- Read-only commitment reports derived from each canonical task's opaque `Verification`
  requirement and current evidence envelopes; no second promise database.
- External-operation records with explicit `pending`, `confirmed`, `failed`, and `unknown`
  states, deterministic replay/conflict handling, and no exactly-once claim.
- Bounded research finding exchange with provenance, expiry, supersession,
  counterexamples, and a next distinguishing test.
- Existing 0.5.1 resume, evidence reconciliation, Completion Passport, causal ledger,
  claim/fencing, native transaction, HUD, and four-platform frozen-package contracts are
  preserved.

## Compatibility boundary

The formal Plugin front door remains the offline, checksum-verified Rust CLI. Python
implementations remain source-checkout oracle and differential-test tooling only; they
are not included in the stable Plugin and are never a runtime fallback.

Contextual recall is opt-in through a versioned manifest that names canonical sources.
Workspaces without that manifest retain the prior resume behavior and receive an
explicit unknown/advisory result instead of guessed context. Existing research
portfolios without findings remain valid.

## Delivery and rollback

DELIVERY requires the repository's local test gates plus a fresh GitHub four-platform
frozen package. Every binary must match the generated SHA-256 manifest and the package
must pass the offline verifier before installation or release publication.

Never relabel a 0.5.1 binary as 0.5.2. If delivery or an external side effect is
ambiguous, preserve the original operation ID, record `unknown`, inspect current
evidence, and reconcile before any retry. Rollback accepts only an untampered receipt
whose operation and digest match the installed target; a conflict fails closed and
preserves the site for manual recovery.
