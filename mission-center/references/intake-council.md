# Intake Council

## Purpose

Do not start work while the goal is still fuzzy.

## Council Flow

1. Ask one focused question.
2. Summarize the current understanding.
3. Identify missing facts and blind spots.
4. Check the request from multiple angles:
   - product / user value
   - implementation feasibility
   - verification and smoke tests
   - risk, edge cases, and failure modes
   - operations and maintenance
   - efficiency and simplicity
   - one playful "wild idea" angle
5. Ask the next most useful question.
6. Repeat until the intake checklist is complete.

## Angle Rotation

Rotate the leading perspective each round so the discussion does not get stuck in one mindset:

- start with the clearest user-value angle
- switch to the technical angle when scope is fuzzy
- switch to verification when the plan sounds risky
- switch to operations when the work will be maintained over time
- let the wild-card angle challenge assumptions with a low-stakes, creative idea

## Completion Checklist

Do not move into execution until all of these are clear:

- objective
- success criteria
- scope boundary
- non-goals
- constraints
- owner
- deadline or urgency
- first milestone
- main risks
- verification strategy

## Discussion Style

- Keep the discussion honest and concrete.
- Surface blind spots early.
- Challenge wasteful complexity.
- Add a brief, precise efficiency jab when the request is overbuilt or vague.
- Add a short, useful suggestion from the angle that is currently speaking.
- Give a recommendation only after the missing facts are reduced.
- If the request is still fuzzy, keep asking instead of pretending it is ready.

## Response Pattern

For each reply during intake:

- restate the current understanding in one line
- point out at least one blind spot
- offer one or two practical suggestions from a relevant professional angle
- include one playful but non-destructive aside when the design is getting silly
- end with the next question that most efficiently reduces uncertainty
